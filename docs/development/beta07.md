# β07の開始点と実装方針

β06の最終コミット[899a47f](https://github.com/shogo314/rusk_b_06/commit/899a47fdc8811dd64e917550ed5459af99a3146e)を引き継ぎ、β07の開発を開始する。β06の[全テストCI](https://github.com/shogo314/rusk_b_06/actions/runs/42463022653)と[ドキュメント公開](https://github.com/shogo314/rusk_b_06/actions/runs/42463022642)の成功を確認して区切った。このリポジトリのGit履歴は新しく開始している。

## 今回の目標

変更・副作用・共有・脱出の情報を中間表現に明示し、解析結果から安全な最適化を行う。言語機能と標準APIはβ06を引き継ぐ。詳しい要件はリポジトリの[design/beta07.md](https://github.com/shogo314/rusk_b_07/blob/main/design/beta07.md)にまとめる。

1. 引数や値への読み取り・中身の更新・コンテナの構造変更・共有先の保持や返却・コールバック呼び出しの効果を表す。
2. HIRで具体的な関数の効果を求め、LIRにも保持・反映する。externや解析できない処理は保守的に扱う。
3. 値が戻り値・コンテナ・フィールド・enum・捕捉などを通じて外へ保持されるかを解析する。
4. 寿命を保証できる一時参照の借用、非脱出スカラーの値保持、不要なコピーや検査の削減へ利用する。
5. 引数・ローカル変数にreadonly/mutable・fixed/rebindable、引数にnoescape/escapeを任意で指定できるようにする。本体・別名・呼び出し・コールバック経由の利用を検査し、別の共有先を含めた不変性は別途解析する。
6. 通常版・最適化無効版の比較、共有と寿命のテスト、サニタイザー、公開問題、ベンチマークで検証する。

## 注釈と自動解析の役割

β07では、次の3組を使う。各性質は独立で、省略時の既定値も明示できる。

| 性質 | 指定 | 省略時 | 対象 |
|---|---|---|---|
| 中身の変更 | `readonly` / `mutable` | `mutable` | 引数・ローカル変数 |
| 名前の結び直し | `fixed` / `rebindable` | `rebindable` | 引数・ローカル変数 |
| 共有の持ち出し | `noescape` / `escape` | `escape` | 引数 |

導入予定の構文例：

```text
readonly fixed let view := values;
mutable rebindable let working := values;
fn sum(readonly noescape a: Vec<Int>) -> Int { ... }
```

readonlyはその名前やそこから得た別名を通じた変更を禁止し、fixedは名前の初期化後の結び直しを禁止する。例えばmutable fixedなら、中身の`=`による更新は可能である。noescapeは引数やその内部への共有を呼び出し終了後まで外へ残さない契約とする。escapeは脱出を許可し、実際に脱出することを要求するものではない。ローカル変数のnoescape/escapeや、フィールド・型全体への一般化は今回の範囲外とする。

これらは意図した契約を実装が破っていないか検査するための任意の注釈である。注釈がなくても本体と呼び出し先を解析し、証明できた読み取り専用・非脱出などの性質をHIR/LIRへ記録する。mutable・rebindable・escapeが明示されていても同じであり、同じ性質が証明できれば同じ最適化へ使う。既存コードに注釈を必須としない。

宣言した契約・解析で証明した性質・externなどの信頼する契約は区別する。解析不能な場合は安全側に扱い、変更しないことと副作用全体がないことを混同しない。readonlyでも別の共有先からの更新は見え、noescapeでもmutableなら更新できる。fixed/rebindable・readonly/mutable・noescape/escapeの初期実装は完了した。

## 戻り値とコールバックの解析

戻り値が引数自身やその内部の要素を共有するのか、独立した新しい値・コピーなのかを解析情報として記録する。共有関係を表す戻り値注釈を利用者に要求するものではない。例えば`return a[0];`の結果はaの要素を共有し、`return copy(a[0]);`は独立した値になる。呼び出し側へ関係を伝え、別名・readonly・寿命の解析に利用する。分岐の候補と不明な由来も保守的に扱う。

コールバックは、処理を任せるために渡す関数値である。即時呼び出し、別の関数への受け渡し、格納・捕捉・遅延イテレータでの保持を区別し、捕捉値への変更や共有、入出力、失敗し得る処理、結果を通じた脱出を解析する。map・filterは遅延走査のためコールバックを保持する。その場で呼ぶだけでも、結果として捕捉値への共有を返し得るので、保存の有無だけでnoescapeとは判断しない。

## 契約違反の診断

readonly・fixed・noescapeの違反箇所と制約の宣言箇所を示し、別名・要素・フィールド・呼び出し・捕捉を経由した違反では、その由来と経路も説明する。解析できず安全を証明できない場合と、明確な違反を区別する。診断の位置・理由・経路をテストし、HIR/LIRの出力でも解析した関係と根拠を確認できるようにする。

これらもβ07の完成条件に含める。fixed・readonly・noescapeの基本的な違反診断は実装済みで、noescapeでは別名・射影・呼び出し結果の段階も表示する。readonlyの詳細な経路、呼び出し先の本体内部の全中間段階、および解析の完成形はこれから実装する。初期解析の実装範囲は次節に記載する。

## 現在の状態

最初の実装として、`src/effects.rs`に関数ごとの効果と戻り値の共有元を求める解析を追加した。**fixed/rebindable・readonly/mutable・noescape/escapeの構文・初期の契約検査は実装済みです。推論した効果を使う引数借用と、閉じたBool・Int・Charの値保持にも対応しました。更新する局所スカラーの値保持と返却、同じ基本ブロック内の安定した配列要素の借用にも対応しました。制御フローや通常の呼び出しをまたぐ要素借用は今後の作業です。** 解析結果はHIR/LIRに保持し、現在は引数借用と閉じたスカラーの値保持にも利用する。

### 初期解析で実装したこと

- 引数ごとの読み取り・更新・構造変更・脱出・外部保持、入出力・外部状態の更新・失敗・非停止の可能性を区別する。各効果は`No`・`May`・`Unknown`で表す。Mayは起こり得るという上限であり、必ず起きるという意味ではない。
- 戻り値が引数自身・配列や文字列の要素・フィールド・enumのpayloadを共有する関係と、戻す集合値の内部に引数への共有を保持する関係を表す。呼び出し側へ関係を代入して伝播する。捕捉環境もIR上のフィールドとして同じ処理を通る。
- LIRの到達可能な制御フローで分岐・ループの状態を結合し、関数間は再帰・相互再帰を含めて固定点まで解析する。CFGの循環と呼び出しの循環は、非停止の可能性として保守的に扱う。
- 情報の出所を`Unanalyzed`・`Inferred`・`Opaque`・`NativeContract`で区別する。引数数・戻り値の参照先・脱出との矛盾・解析上限をHIR/LIRで検証する。

例えば`fn identity(x: Int) -> Int { return x; }`では、更新しないが引数自身への共有を返すと分かる。`fn value(x: Int) -> Int { x := 7; return x; }`では、引数名の結び直しと共有オブジェクトの更新を区別し、引数への共有を返さないと分かる。

`rusk compile main.rusk --emit hir -o main.hir`または`--emit lir`で、各関数の`effects`を確認できる。戻り値の`result_path`は結果の内部の位置、`parameter`は0始まりの引数番号、`parameter_path`は引数の内部の位置を表す。`fresh`は独立した新規オブジェクトを返す可能性であって、一意所有の証明ではない。最適化の有無で解析情報は変えない。

### 現段階の保守的な扱い

組み込みランタイムの基本操作には、宣言の`effects`プロパティで明示した効果契約を登録する。`lib/core.rusk`の基本演算・コピー・変換・入出力・文字列操作・sumと、`lib/vec.rusk`の長さ・添字取得・真偽変換・空配列構築が対象である。`src/native_effects.rs`でターゲット非依存の情報へ変換し、返却する要素の型と経路も検証する。情報の出所は`NativeContract`であり、Rusk本体を解析した`Inferred`とは区別する。

これは組み込みC++実装との信頼境界であり、ユーザーが書くreadonly等の注釈とは別の内部プロパティである。組み込みランタイム以外での指定は拒否する。関数名やC++コードの見た目から契約を推測しない。未登録の外部実装・コンテナ操作・コールバックを呼ぶネイティブ処理は、引き続きOpaque・Unknownとして保守的に扱う。

フィールドへの格納や変更し得る呼び出しの後では、ヒープの投影を保守的に不明へ広げる。変更前に取得済みの共有は区別する。直接構築した格納先の別名群が関数内に留まると証明できた場合を除き、局所オブジェクトへの格納も脱出の可能性として扱う。直接構築した入れ子の格納先は共有先と到達関係を追跡する。既知の読み取り専用・外部非保持の関数が引数自身や内部を共有して返す場合も追跡する。返却する集約の内部の共有も、元の共有先への到達関係を追跡する。配列操作や返却された格納先の私的性まで精度を高めるには、さらに解析が必要である。引数ごとの更新情報は、その引数を経由したアクセスを表す。異なる引数が互いに共有していないとは仮定せず、更新なしという情報だけで別の共有先からの更新もないとは判断しない。

共有元の候補が64個、経路が16段を超えた場合は不明へ広げる。上限を超えた関係を安全とは扱わない。注釈なしでは利用できる最適化が減り、注釈した契約を証明できない場合には、その理由を診断して拒否する。

初期の回帰テストでは、共有と独立値、ローカルな結び直し、格納した共有、フィールド取得、関数間の伝播、捕捉した共有の返却、分岐・ループ・相互再帰、外部処理、変更による情報の失効、解析上限、壊れた情報の拒否を検証する。生成C++はβ06と全172例でバイト単位に一致した。 初期解析の10単体テストとIRへの保持を確認する統合テストを追加し、最終状態で通常285テスト、最適化無効161テスト、fmt、Clippy、MkDocsのstrictビルドが成功した。C++の表現・実行処理は変更していないため、この段階ではサニタイザーと公開ジャッジの全ケースは再実行していない。


## 返却と外部保持を分けた脱出の伝播

`escape`は戻り値を含めて呼び出し終了後へ共有が残る可能性、`retained`は戻り値以外の格納先へ保持される可能性を表す。要素を共有して返すgetterはescapeがMayでも、retainedはNoである。呼び出し元はその戻り値の利用を追跡し、受け取っただけで自身の引数が外へ脱出したとは判定しない。

```rusk
fn first(a: Vec<Int>) -> Int { return a[0]; }
fn detached(a: Vec<Int>) -> Int { return copy(first(a)); }
fn ignored(a: Vec<Int>) { first(a); }
```

firstは要素への共有を返すためaのescapeがMay、detachedとignoredはNoになる。detachedの結果は独立した値である。いずれもaの中身を更新せず、外部の格納先へ共有を保持しないのでwriteとretainedはNoになる。添字が不正なら失敗する可能性は残す。

標準の整数加算・代入・sumなども契約から効果を伝播できる。加算やsumのオーバーフロー、入力・変換・添字の失敗、入出力やブロックする可能性、文字列更新の構造変更を記録する。効果が不明なものを純粋と扱ったり、読み取り専用だから失敗や入出力もないと扱ったりしない。

この段階では脱出伝播の単体テスト、契約の型・形の検証、実際のソースからの効果推論・信頼境界・共有の動作を検査する`tests/effects.rs`を追加し、共通入口の最適化無効版にも含めた。通常295テスト・最適化無効167テスト・fmt・Clippy・MkDocsのstrictビルドで成功した。生成C++は引き続きβ06の172例と一致する。新しい借用・スカラー最適化にはまだ適用していない。

## 引き継いだ課題と測定

[β06の生成C++の調査](beta06.md)で、Rusk版find・sumの反復で一時的なshared_ptrのコピーと参照カウント操作が多いことを確認した。findは通常のRusk関数へ移行済みで、速度退行が残る。sumは既存のextern実装を維持している。

β07ではfindの移行時退行を対象にし、sumもRusk実装と既存実装を比較して移行を判断する。特定の関数名だけの専用処理に偏らず、通常のRusk関数へ適用できる解析とする。既存の11項目の測定も維持する。

比較用に、β06のソースを`/tmp/rusk_b_06-899a47f.tar.gz`、リリース版コンパイラを`/tmp/rusk-beta06-baseline`へ保存した。環境が変わった場合はβ06の最終コミットから再ビルドする。[開始点の情報](beta07-baseline.json)にコミット・検証結果・比較用コンパイラのハッシュを記録する。

## 守る規則

`=`と`:=`、共有・コピー・評価順、更新の可視性、文字参照と走査中の変更検査、取得済み要素の寿命、位置付き実行時診断を維持する。実験用C++の借用への置換や検査削除を、そのまま一般のプログラムへ適用することはしない。解析結果から安全を説明できる範囲で実装する。

## fixed / rebindableの実装

let・関数引数・無名関数引数の結び直し注釈をASTからHIR/LIRまで保持する。初期化済みの名前に対する直接の結び直しと捕捉経由の結び直しを検査し、LIRの制御フローでは初期化された可能性のある名前の集合を合流・反復させる。Releaseは初期化の履歴を消さず、新しいDeclareでリセットする。要素やフィールドの変更とは区別し、注釈はC++生成時には処理を追加しない。

分岐・ループ・ラベル・ガード・分解・ジェネリック・捕捉と、診断位置をテストする。[利用できる構文と制約](../reference/bindings.md)を参照。ほかの注釈の例は引き続き計画である。

この段階の検証では、通常の306件と`--no-opt`の175件、Formatting・Clippy、厳格なドキュメントビルドが通過した。既存172例の生成C++はβ06とバイト単位で一致した。

## readonly / mutableの初期実装

`src/readonly.rs`で読み取り専用のアクセス経路をLIR上で追跡する。明示した契約はAST・HIR・LIRへ保持し、関数の効果要約から、注釈のない呼び出し先が行う変更も検査する。関数ごとの戻り値・保持に含まれる制約を固定点まで伝播してから違反を診断する。独立したコピーと共有を区別し、再帰・分岐・反復・捕捉・コールバックにも適用する。

要約はHIR/LIRの`access`に保存し、射影先の型や契約の由来を検証する。C++生成では注釈を無視する。読み取り専用の値をヒープへ格納した後は、オブジェクトごとの共有先をまだ追跡せずに広く制約を合流させる。この保守的な処理や外部実装の不明性による拒否は、既知の変更と区別して診断する。[利用できる構文と現時点の制限](../reference/access.md)を参照。

配列の追加・要素置換には、変更対象・保持する引数・返却する別名を示す信頼契約を追加した。深いコピー・代入・出力は基本型と入れ子の配列に限って登録する。レコードや外部型を含む場合はユーザー定義の処理を呼び得るため、従来どおりOpaqueとして扱う。残る作業は共有先の解析精度、新しい最適化と性能評価、詳細な診断経路である。

この段階では通常318件・`--no-opt`184件、Formatting・Clippy、Sanitizers22件、厳格なドキュメントビルドが通過した。既存172例の生成C++はβ06とバイト単位で一致した。

## noescape / escapeの初期実装

引数の持ち出し契約をASTとHIR/LIRの`AnnotateEscape`へ保持し、固定点に達した関数効果のescapeを検査する。宣言で推論結果を上書きせず、明示したescapeも非脱出の推論を妨げない。引数名を結び直した後の値と元の共有元を区別し、共有した要素・フィールド・payload・捕捉・戻り値や外部格納も扱う。返却だけを行う呼び出し先の結果をコピー・破棄する場合は、呼び出し元の脱出としない。

違反する関数は、最終的な呼び出し先の要約を使って制御フローを再走査し、返却・保存・呼び出しの位置と射影経路を示す。HIR/LIRへreturnの位置も追加した。注釈の引数番号・重複をIR検証で検査し、注釈自体はC++へ処理を追加しない。

Optionの構築・判定・値取得、および引数を取らない既知の構築処理の効果を登録した。Someの引数は戻り値のpayloadを通じて脱出し、valueはpayloadへの共有を返すが、戻り値以外には保持しない。try_readのIO・失敗・待機の可能性も残す。フィールド格納や未解析のネイティブ操作などでは保守的な拒否が残る。[構文・診断・制約](../reference/escape.md)を参照。

この段階では通常328件・`--no-opt`192件、Formatting・Clippy、Sanitizers23件、厳格なドキュメントビルドが通過した。既存172例の生成C++はβ06とバイト単位で一致した。新しい予約語escapeと衝突した最適化テストのRusk関数名を変更し、通常版の全ターゲットを再実行して成功を確認した。

## 共有先の追跡と最初の最適化

既知のローカルオブジェクトを割り当て位置のIDで追跡し、別名・フィールド・payload・返却した集約の共有関係を保持する。追跡外へ公開したオブジェクトとその子を区別し、不明な格納先や呼び出しには保守的な扱いを維持する。readonlyの私的な格納を、無関係な呼び出し元の格納先へ無条件には伝えない。noescapeの一般的な効果解析は引き続き保守的である。

推論した更新・構造変更・脱出がNoで、外部書き込みもNoのRusk関数引数をC++のconst Obj<T>&で受け取る。さらに既知の新しいBoolから共有する閉じた別名群を調べ、スカラー演算内だけで使う場合に値と参照で保持する。名前の結び直し・更新・捕捉・格納・返却・通常の関数への受け渡しがある場合は所有を維持する。最適化無効版では従来の表現を使う。

通常341件・最適化無効199件・Sanitizers24件・公開ジャッジ49解答の検証が成功した。既存11ベンチマークとfind・sum・関数呼び出しを測定し、全入力の一致を確認した。findは約1.31倍改善したが、Rusk版sumは依然として約6.8倍遅く、移行しない。詳細な条件・確保数・参照数・各回の測定値は[共有先解析と最適化の記録](beta07-performance.md)にまとめた。

## 閉じたスカラーの値保持をInt・Charへ拡張

Boolに使っていた別名群の解析を`src/backend/scalar_aliases.rs`へ移し、Int・Charにも適用する。新しいリテラルや生成済みスカラー演算の結果を元とし、更新・結び直し・捕捉・格納・返却・通常の関数への受け渡しがない場合に限り、別名を同じ値保持領域へのC++参照にする。引数や既存の要素・文字参照を新しい独立値とみなすことはない。最適化無効版は従来の所有表現を使う。

## 安定した配列要素の直接借用

所有する要素の閉じた別名群について、取得から元の最後の解放まで、同じ基本ブロック内で配列スロットを直接借用する。対象はInt・Bool・Charで、組み込みVecの添字取得・Iterの次要素取得だけとする。C++では取得結果を`const Obj<T>&`で保持し、次要素取得のlambdaも参照を返す。要素の値をコピーしないため、別の共有先からのスカラー更新は引き続き見える。

群の定義・利用・解放が一つの基本ブロックに閉じ、一つの定義と一度の解放があるという既存の検証を前提とする。追加の走査で、取得元のVecまたはIterが最後の利用まで解放されないこと、名前・フィールドの結び直しや未対応の呼び出しが区間に入らないことを確認する。許可する呼び出しは組み込みの直接生成に対応したものだけで、要素スロットの置換・構造変更・利用者のコールバックを実行しない。配列自身はVecまたはIterの所有するObjが保持する。元の解放の順番で判定し、取得元の寿命は延長しない。外部実装が返したObjは基本型でも独自の解放処理を持ち得るため、所有操作・解放も既知のfreshな一時値、値保持が証明済みの群、または現在借用中の群に限定し、それ以外では借用を打ち切る。

要素の別名の更新・返却・捕捉・集約への保存・通常の関数への受け渡しは、既存の閉じた群の検証で除外する。要素の置換・追加・通常の関数呼び出しや結び直しが借用区間に入る場合や、取得元が先に解放される場合は、従来どおり要素を所有する。分岐・反復をまたぐ要素の保持にも適用しない。取得時の範囲検査・走査の世代検査・終端検査・添字更新とエラー位置は維持する。

回帰テストで配列の累積、Bool・Charの走査、別の共有先からの値更新、文字参照の解放、取得元のスコープ終了、外部値の独自の解放処理、要素の置換・通常の呼び出し・結び直し時の所有へのフォールバックを最適化無効版と比較する。生成C++で参照返却と所有者のresetの除去を確認し、寿命と解放はサニタイザーでも検証する。

通常371件・最適化無効221件・ASan/UBSan/LeakSanitizer32件・公開ジャッジ51解答、Formatting・Clippy・MkDocs strictが成功した。公開ジャッジでは有効な検証キャッシュも再利用した。各7回の測定でRusk版sumは約107→52ms、共有ポインタコピーは約2千万→126回となった。既存sumは約48msで約9%の差が残るため、移行は見送る。既存11項目、入出力各11回の追加測定、生成C++とELF .textの一致確認も含め、全結果は[性能記録](beta07-performance.md)に保存した。通常の関数や制御フローをまたぐ要素借用は引き続き残る。
